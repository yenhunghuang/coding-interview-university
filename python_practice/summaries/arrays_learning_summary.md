## 🧠 核心概念理解

### 時間複雜度總結

| 操作 | 時間複雜度 | 說明 |
|------|-----------|------|
| `push()` | O(1) amortized | 平攤後為常數時間 |
| `pop()` | O(1) amortized | 平攤後為常數時間 |
| `at(index)` | O(1) | 直接存取，常數時間 |
| `insert(index)` | O(n) | 需要移動元素，線性時間 |
| `delete(index)` | O(n) | 需要移動元素，線性時間 |
| `find(item)` | O(n) | 最壞情況需要搜尋全部 |

### Amortized Analysis (平攤分析)

**什麼是 Amortized O(1)？**
- 大部分 push 操作是 O(1)
- 偶爾需要擴容時是 O(n)
- 平均下來，每個操作是 O(1)

**擴容策略：**
- 容量滿時，擴大至 2 倍
- 使用量低於 1/4 時，縮小至 1/2

## 🔍 Arrays 的優缺點

### ✅ 優點
1. **隨機存取快速**: O(1) 時間存取任何元素
2. **記憶體連續**: 快取友善，存取效率高
3. **空間效率**: 沒有額外的指標開銷
4. **實作簡單**: 相對容易理解和實作

### ❌ 缺點
1. **插入/刪除慢**: 非尾端操作需要 O(n) 時間
2. **大小固定**: 靜態陣列無法動態調整
3. **擴容開銷**: 動態陣列偶爾需要 O(n) 時間擴容
4. **記憶體浪費**: 可能有未使用的預分配空間

## 🆚 何時使用 Arrays？

### 適合的情況
- **頻繁隨機存取**: 需要快速存取任意位置的元素
- **數值計算**: 數學運算、統計分析
- **實現其他數據結構**: 堆積、雜湊表等
- **記憶體敏感應用**: 需要最小化記憶體開銷

### 不適合的情況
- **頻繁插入/刪除**: 特別是在陣列中間
- **大小變動頻繁**: 無法預估大小的情況
- **順序存取為主**: 不需要隨機存取的應用
